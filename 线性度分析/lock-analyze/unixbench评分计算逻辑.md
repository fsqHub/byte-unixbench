# UnixBench 最终分数计算逻辑

> 基于 `UnixBench/Run` 脚本源码和 `pgms/index.base` 基线文件的分析。

---

## 一、单项分数 (Index Score)

每个测试项的分数计算公式：

```
单项 Index = (测试实际得分 / 基线得分) × 10
```

基线来自 `pgms/index.base` 文件，参考机器是一台 **SPARCstation 20-61**（代号 "George"，约 1992 年的工作站）。

**示例**：`execl` 的基线是 **43.0 lps**，如果你的机器跑出 4300 lps，则：
```
execl index = (4300 / 43.0) × 10 = 1000.0
```

index 值 1000.0 表示性能是基线机器的 **100 倍**。

---

## 二、最终总分 (System Benchmark Index Score)

总分是 **所有参与 index 的测试项 ratio 值的几何平均数 × 10**。

源码实现（`Run` 第 1272-1281 行）：

```perl
# 对每项测试，累加 ln(ratio)
$sum{$cat} += log($ratio);    # ratio = 实际得分 / 基线得分

# 最终计算几何平均
$results->{'index'}{$cat} = exp($sum / $count) * 10;
```

数学公式：

```
总分 = exp( (ln(r₁) + ln(r₂) + ... + ln(rₙ)) / N ) × 10
     = (r₁ × r₂ × ... × rₙ)^(1/N) × 10
```

其中 `rᵢ = 实际得分ᵢ / 基线得分ᵢ`，N = 参与计算的测试项数量。

定义在 `Run` 文件第 144-146 行：

```perl
my $index = [
   "dhry2reg", "whetstone-double", @$oldsystem, "shell1", "shell8"
```

## 四、各项的"权重"分析

### 4.1 几何平均的特性：没有显式权重，但短板效应极强

几何平均中每项的 **数学权重完全相等**（各占 1/12）。但其实际影响力取决于 **偏离倍数**：

```
假设 12 项中 11 项的 ratio 都是 100（性能是基线的 100 倍）
只有 execl 的 ratio 是 1（与基线持平）

总分 = (100¹¹ × 1)^(1/12) × 10
     = 100^(11/12) × 10
     = 69.5 × 10 = 695

如果 execl 也是 100：
总分 = 100^(12/12) × 10 = 1000
```

**一项从 100 跌到 1，总分从 1000 跌到 695（-30.5%）**。

### 4.2 按测试分类的分布

| 分类 | 测试项 | 数量 | 占比 |
|---|---|:---:|:---:|
| **CPU 计算** | dhry2reg, whetstone-double | 2 | 16.7% |
| **进程管理** | execl, spawn | 2 | 16.7% |
| **文件 IO** | fstime, fsbuffer, fsdisk | 3 | 25.0% |
| **IPC** | pipe | 1 | 8.3% |
| **调度** | context1 | 1 | 8.3% |
| **内核** | syscall | 1 | 8.3% |
| **综合** | shell1, shell8 | 2 | 16.7% |

### 4.3 容器线性度场景的影响

与进程创建/exec 强相关的测试项：

| 测试项 | 涉及 fork | 涉及 exec | 占比 |
|---|:---:|:---:|---|
| `execl` | ✗ | ✓ | 1/12 |
| `spawn` | ✓ | ✗ | 1/12 |
| `shell1` | ✓ | ✓ | 1/12 |
| `shell8` | ✓ | ✓ | 1/12 |
| **合计** | | | **4/12 = 33%** |

这 4 项在容器高并发下都会遭遇相同的内核锁竞争（`i_mmap_rwsem`、`mmap_lock`、`tasklist_lock` 等），当它们集体跌到基线附近甚至以下时，几何平均的短板效应会导致总分 **断崖式下跌**。

## 五、计算示例

假设单容器测试结果：

| 测试项 | 实际得分 | 基线 | ratio | 单项 index |
|---|---:|---:|---:|---:|
| dhry2reg | 50,000,000 | 116,700 | 428.4 | 4284.5 |
| whetstone-double | 5,000 | 55.0 | 90.9 | 909.1 |
| execl | 6,000 | 43.0 | 139.5 | 1395.3 |
| ... | ... | ... | ... | ... |

```
总分 = (428.4 × 90.9 × 139.5 × ...)^(1/12) × 10
```

如果整机满载时 `execl` 从 6000 跌到 150（ratio 从 139.5 跌到 3.5），
`spawn` 类似跌到 ratio 5，`shell1/shell8` 也跌到 ratio 2-3，
仅这 4 项的拖拽就能让总分跌去 **50% 以上**。
